# Guards: the full enforcement catalog

Ten hook scripts on nine Claude Code events, one gate with eleven lines, deny rules in the project's settings, and roles with write scopes. Every sentence quoted here is printed by a script under `tools/`; the file names are the source. The guards stop an agent's everyday mistakes and say why, so the agent learns the rule from the refusal. They are not an operating-system sandbox; the last section says what a deliberate person can still do and why the kit leaves it there.

## Why hooks and not prompts

A prompt rule is weighed against everything else in the context and loses on the long day. A hook runs before the tool call, exits 2, and the tool does not run; the model reads one sentence that names the rule. Four of the hooks carry `onFailure: block`, and every guard catches its own exceptions and denies (a stop hook blocks), so a guard that crashes or times out blocks instead of letting the action through, and `init` writes permission deny rules that Claude Code enforces in every mode, hooks or no hooks. The hooks explain; the deny rules hold.

## The ten hooks

`hooks/hooks.json` registers them. Each reads the hook JSON from stdin (anything unreadable, `null` included, is an empty event), finds the project root (the hook's `cwd`, or the closest parent with `.git` or `AGENTS.md`), and resolves the role from `agent_type` (`sdlc-kit:builder` arrives with the plugin prefix; the match is on the part after the last colon; no `agent_type` is the main session; an agent the kit does not define gets the main rules). A PreToolUse denial is exit code 2 and one sentence on stderr; a Stop or SubagentStop block is `{"decision":"block","reason":...}`; the advisory hooks add context and never block.

### Human-only files and the human's signatures

Refused to every role by both guards, by Edit, Write, MCP tool or shell: `AGENTS.md`, `CLAUDE.md`, `.claude/settings.json`, `.claude/settings.local.json`, `docs/decisions/**` (a role whose own paths name it may write a decision that does not exist yet or is still `Status: proposed`), `.sdlc/**`, `docs/review/<cycle>/decisions.json`, any document under `docs/` once it carries `Status: approved` or `accepted` (the requirements, the plan, a UI spec, an ADR), `.claude/skills/domain-*/**` and `.claude/skills/legal-*/**` once the file exists, `.githooks/*` and `.github/**` unless the content is the kit's own template (`chmod +x` on the hooks is the one shell change allowed), anything outside the project, and the kit's own files.

The verifier's answer is captured by the SubagentStop hook itself into `docs/review/<cycle>/verifier.captured.txt`, and `review.mjs render` reads that file; the copy the clerk saves as `verifier.json` is for people. An equivalence judgment that exists only in the clerk's copy is not recorded and the survivor counts as real (the review says so in a clerk note), so the strict gate's exemptions never come from a file an agent wrote. The review's rendered files are the scripts' and no role writes them either: `docs/REVIEW.md`, `docs/REQUIREMENTS-REVIEW.md`, `docs/review/state.json`, the briefs and `findings.json` (`review.mjs render` and `reqreview.mjs render` write them from the agents' answers; the clerk saves only `finder-*.json`, `verifier.json`, `verifier.txt` and the role answer files), and the gate's `review` line cross-checks `docs/REVIEW.md` against `state.json`, so a verdict typed by hand does not pass. Three lines are the human's signature and no role writes them, by any tool: `Status: approved` or `Status: accepted` in a document (judged on the file as it would read after the edit, so a two-step edit or a `replace_all` does not get there either), a ticked manual check `- [x]` in `docs/MANUAL-CHECKS.md` (a check is appended unticked, by Edit or by `echo "- [ ] ..." >>`; nothing else touches the file through the shell), and a `decisions.json` (written by `review.mjs decide`, which no role may run).

Sentences: `Denied: AGENTS.md is a human decision file; the human edits it, you ask.`, `Denied: docs/REQUIREMENTS.md is approved, changing a requirement is a human decision; the human edits it, you ask.`, `Denied: docs/PLAN.md is approved (its Status line); changing it is a human decision; the human edits it, you ask.`, `Denied: docs/PLAN.md would carry "Status: approved" (or accepted), and that line is the human's signature; leave it as proposed or draft, the human approves.`, `Denied: docs/MANUAL-CHECKS.md would gain a ticked check (- [x] R-06 ...); a tick is the human's signature that they ran the check, add checks unticked.`, `Denied: .githooks/pre-commit is the gate's own installation; it holds the kit's template as /sdlc-kit:init writes it, and any other content (a disabled hook, a changed workflow) is the human's decision.`, `Denied: tools/gate.mjs is part of the kit (hooks, tools, agents); the kit changes in its own repository, not from a project session.`

Everything the guards read must be a regular file: a folder or a link where `.sdlc/slice` or a document should be reads as empty, and `mkdir` under `.sdlc/` is refused except for `.sdlc` itself. The slice marker `.sdlc/slice` has its own rules: `echo S<n> > .sdlc/slice` needs an approved plan and no active slice (`Denied: S3 is active; finish it and run rm .sdlc/slice after the commit before starting another slice.`); `rm .sdlc/slice` needs green tests and the slice's files committed (`Denied: S3 is active and 2 of its files are not committed (src/domain/lines.js, tests/lines.test.js); commit through the gate before rm .sdlc/slice, or ask the human to close the slice.`). `docs/PLAN.md` cannot change while a slice is active: `a wider slice is a human decision`. Documents under `docs/` are written with Edit or Write, never through the shell, so their content can be checked: `Denied: docs/notes.md is a document; documents are written with the Edit or Write tool so their content (an approval line among it) can be checked, never through the shell.`

## Roles and `x-writes`: the write matrix

A role is an agent file under `agents/`. The frontmatter key `x-writes` is a kit convention: Claude Code ignores it, the hooks read it. Why a matrix and not a sentence in each prompt: the hooks compare a path against a list and refuse in code, so the matrix holds for a tired model, a long context and a prompt injection alike.

| `x-writes` | Meaning | Roles today |
|---|---|---|
| `slice` | the active slice's `**Files:**` plus `docs/MANUAL-CHECKS.md`; `docs/**` with no slice | `builder` (sonnet, `maxTurns` 120, `effort` medium, no `Agent` tool) |
| `[]` or missing | a judge: nothing, by any tool; and it spawns nothing | the finders `finder-correctness`, `finder-security`, `finder-contract`, `finder-domain`, `finder-legal` (opus); `product-owner`, `domain-expert`, `legal` (opus); `verifier` (fable, `maxTurns` 80, `effort` max); all with `disallowedTools: Agent, Edit, Write, MultiEdit, NotebookEdit` as a second wall |
| a list of patterns (`[docs/PLAN.md, tests/**/*.spec.mjs]`) | those paths and nothing else, slice or no slice; `**` any segments, `*` inside one, a trailing `/` the whole folder; such a role may propose a decision (`docs/decisions/ADR-*.md`, new or `Status: proposed`) when its patterns name it, and the tester's `.spec` files are its alone | the v2 roles (analyst, architect, planner, tester, devops); the hooks and tests are ready, the agent files land with v2 |
| `main` (no `agent_type`) | the active slice's files plus its own notes under `docs/**` (not the plan), or `docs/**`, the init files and `.claude/skills/**` (by `Write`, whole file) with no slice | the main session, the clerk |

Human-only files and the content rules apply to every role whatever its patterns say. The tester's spec files (`tests/**/*.spec.mjs`) are never changed or removed by the builder or the main session: `Denied: tests/customers.spec.mjs is the tester's test (a .spec file); the builder makes it pass and adds its own tests in a .test file, it never changes or removes the tester's.` `node tools/roles.mjs` prints the table; `node tools/roles.mjs sdlc-kit:builder` prints the role one `agent_type` resolves to.

```
gate     review   3f9c2d1 ok, verdict MERGE
GATE PASS
```

A failed line ends in `<- FAIL`, a warning in `<- WARN`; a warning does not fail the gate.

| Flag | Effect | Used by |
|---|---|---|
| none | scope on the changed files, trace on all MUSTs | the skills, `init` |
| `--staged` | scope and secrets on the staged files | `pre-commit`, the commit guard |
| `--message "..."`, `--message-file <path>` | also checks the commit subject | the commit guard, `commit-msg` |
| `--only commit` | only the message | `commit-msg` |
| `--review` | adds the `ci` and `review` lines as warnings | `ship` |
| `--strict` | a manual check counts only when ticked `[x]`; `ci` and `review` fail instead of warning; `secrets` also scans the commits (the pull request's range from `GITHUB_BASE_REF`, else the last commit); a `mutations` line runs the full `mutate.mjs` and fails on any survivor the latest verifier did not mark equivalent | CI |
| `--root <dir>` | another project root | tests |

The default gate plants no defects; a strict run takes up to a minute on a small app (the workflow sets `timeout-minutes: 30`).

| Line | What it checks and why | Text when it fails |
|---|---|---|
| `tests` | `node --test` in the project: the one measurement everything else leans on | `1 passed, 1 failed: R-02 rejects an empty name` |
| `scope` | changed or staged files against the active slice's `**Files:**` (plus `docs/MANUAL-CHECKS.md`), or `docs/**`, the init files and `.claude/skills/**` with no slice; `.sdlc/` and `.sdlc-kit/` are never listed; not checked outside a git repository or before a plan exists | `S3: index.html is not in the plan (allowed: ...)` or `no slice active: src/x.js is outside docs/ (start a slice with /sdlc-kit:implement-slice S<n>)` |
| `trace` | every MUST (of the active slice, or all) has a test title with its ID or a manual check (listed, or ticked under `--strict`); every ID used exists. Why: a requirement with no test and no check is a wish | `S3: 7 MUST, 1 missing (R-12), 0 orphan IDs` or `... 1 orphan IDs (not defined: R-99)` |
| `contract` | every approved document under `docs/` is as it was in the commit that approved it (`tools/contract.mjs`, from git history, renames followed). Why: the approval is a git fact, so CI computes the same answer as the terminal and there is no state file to lose | `docs/PLAN.md changed in 1 commit after its approval in 8b3d2e1 (c4d5e6f)` or `docs/REQUIREMENTS.md approved but not committed yet` |
| `secrets` | no secret-named file among the changes; no credential shape in the added lines (a private key, an AWS key, a GitHub, Slack or API token, a JWT, a password or key with a literal value; the vendors' documented placeholders are stripped first; a JWT or a password under `tests/` is a fixture). An unreadable diff fails the line instead of passing it | `src/config.js adds an AWS access key; secrets never enter the repository` or `the diff could not be read (git failed or the change is too large to scan); make the change smaller` |
| `deps` | a dependency manifest or lockfile among the changes (`package.json`, lockfiles of npm, yarn, pnpm, bun, Python, Go, Rust, Ruby, PHP): fails inside a slice, warns outside one. Why: a dependency is a human decision (ADR-001) | `package.json changed; a dependency is a human decision (ADR-001), not a S3 change` |
| `slice` | a slice names more than six files: a warning, the plan is the human's | `S3 names 8 files, more than the 6 the plan format allows; split it next time` |
| `commit` | subject `S<n>: ... (R-xx, R-yy)` (ranges `R-11..R-17`), IDs exist, `S<n>` is the active slice; IDs outside the slice's `**Covers:**` are a warning; a docs-only commit with no slice takes any message | `"fix stuff" must look like S<n>: what changed (R-xx, R-yy)` or `"S2: ..." names S2 but S3 is active (.sdlc/slice)` |
| `ci` | `.github/workflows/gate.yml` exists and pins the kit checkout to a full 40-hex sha (read inside that step's own `with:` block). Why: CI must run the gate the developer ran, not whatever `main` is tomorrow | `.github/workflows/gate.yml pins the kit to "main", not a full 40-hex sha` |
| `review` | `docs/REVIEW.md` has `Reviewed: <sha>`, no code commit follows it on the branch (docs-only commits are fine; on a pull request's merge commit the branch tip is measured, not the base's new commits), verdict `MERGE` | `none (run /sdlc-kit:review-change)`, `3f9c2d1 is 2 commits old (a1b2c3d S4: ...): re-review needed`, `3f9c2d1 ok, verdict FIX FIRST` |
| `mutations` | `--strict` only: `mutate.mjs` over every site; survivors the latest rendered review judged equivalent are excluded, read from `docs/review/state.json` as `review.mjs render` recorded them (never from the verifier's answer file the clerk saved) | `196 planted, 194 caught, 2 survived, 1 equivalent (verifier, cycle 1) (src/domain/money.js:14 "<=" -> "<")` |

Same gate, three callers: the Claude hook (fast path while the AI works), `.githooks/pre-commit` and `commit-msg` (any tool, any human; they read the kit path from `.sdlc/kit-path` and say `run /sdlc-kit:init` when it is missing; `core.hooksPath` is local configuration, so every fresh clone runs `/sdlc-kit:init` once or nothing fires), `.github/workflows/gate.yml` (the pipeline, `--strict`, which checks the kit out at the pinned sha into `.sdlc-kit` on Node 22; `init` says when that sha is not pushed yet).

## Deny rules

`init` merges these into `.claude/settings.json` under `permissions.deny` (rules already there are kept). Claude Code enforces them in every permission mode, hooks or no hooks, so the most expensive mistakes hold even when a hook is disabled or times out:

`Read(./.env)`, `Read(./.env.*)`, `Read(./secrets/**)`, `Read(./**/*.pem)`, `Read(./**/*.key)`, `Bash(git push *)`, `Bash(git push)`, `Bash(git tag *)`, `Bash(git commit --no-verify *)`, `Bash(git commit -n *)`, `Bash(npm install *)`, `Bash(npm i *)`, `Bash(npm ci)`, `Bash(npm ci *)`, `Bash(npm add *)`, `Bash(npx *)`, `Bash(gh pr create *)`, `Bash(gh pr merge *)`, `Bash(gh release *)`, `Bash(git branch -D *)`, `Bash(git reset --hard *)`, `Bash(printenv)`, `Bash(env)`.

## Gate catalog: measured, judged, human

Three kinds. **Measured**: a script decides, exit code and one line. **Judged**: a reviewer agent decides from evidence; it can fail the review, it cannot pass it alone. **Human**: a person decides from what is on screen.

| Check | Kind | Where | Invariant |
|---|---|---|---|
| tests (`node --test` green) | measured | gate line `tests`; after every edit (hook); before every commit (hook, git hook); CI | yes |
| scope (changed files on the slice's `**Files:**` line; docs only with no slice) | measured | scope guard before the write; shell writes, `git rm`, `git mv` in the commit guard; gate line `scope` before the commit | yes |
| the write matrix (`x-writes` per agent file) | measured | scope guard, commit guard, agent guard | yes |
| human-only files, approved documents, the human's signatures | measured | scope guard, commit guard (Edit, Write, MCP and shell writes alike); gate line `contract` | yes |
| secrets (named files, globs, environment dumps, credential shapes in a diff) | measured | secret guard before the read or write; gate line `secrets`; deny rules; CI | yes |
| content words (HTML sinks, unfinished work, debug output in ui and domain code, weak tests, a shrinking rewrite) | measured | scope guard | no |
| trace (every MUST has a test title with its id or a manual check; `--strict` wants `[x]`) | measured | gate line `trace`; CI | no |
| commit message (`S<n>: ... (R-xx)`, `S<n>` is the active slice, IDs exist) | measured | gate line `commit`; `commit-msg` hook | no |
| dependencies (a manifest or lockfile change is a human decision) | measured | commit guard on the install commands; gate line `deps`; deny rules | yes |
| review binding (`Reviewed: <sha>` on the branch tip, verdict `MERGE`) and the CI pin | measured | gate lines `review`, `ci`: ship warns, `--strict` fails | no |
| planted defects (every one caught, verifier-judged equivalents excluded) | measured | `mutate.mjs --min 1`; gate line `mutations` in `--strict`; the review header | no |
| the right agent at the right step (builder on an approved plan, verifier not on the author's model, a judge spawning nothing) | measured | agent guard before the spawn | yes |
| a judge answers JSON; a builder ends green and committed | measured | SubagentStop, once per agent | no |
| findings (four classes, five with a domain skill, typed, with evidence; a `DOM` or `LEG` finding cites a rule a skill defines) | judged | the finders | no |
| requirements review items (business flow, domain rules, legal rules, typed, with the text to fold in) | judged | the product owner, the domain expert and the legal role; `reqreview.mjs` validates, the human ticks | no |
| the pass (every finding placed, level named, planted defects judged) | judged + measured | the verifier; `review.mjs` decides the verdict | no |
| approve the requirements and the plan, accept an ADR, answer `Q-nn` and the decision package, tick manual checks, accept or reject each confirmed finding (`decide`), open and approve the PR | human | `Status: approved`, `Status: accepted`; `## Answered` in an ADR; `[x]` in `docs/MANUAL-CHECKS.md`; `decisions.json`; the PR | yes |

"Invariant" means the check holds at every moment of a session, not only at a commit or a review. Test-first is the one rule the builder is told rather than measured; the verifier's planted defects show afterwards whether the tests can fail.

## Not a sandbox: what a deliberate person can still do

The guards are built for an agent's everyday mistakes and for the obvious shortcuts; they are not an operating-system sandbox, and the kit says so rather than pretending. The adversarial audit of the guards (66 cases, run against the hooks with hand-written events) left these open on purpose, each with the reason:

- **A program read from a file runs with the developer's rights.** `node tests/x.test.js` and `sh ./run.sh` are allowed: the kit cannot read a program's intent, and a test suite must be able to run. One-liners and programs piped into an interpreter are refused for every role, no program may be written under `docs/` or `.claude/`, and an interpreter runs only a file inside the project (or a kit tool), never one in the temp folder, so the program has to be a slice file, where the scope guard saw it written and the review reads it. A test that writes `AGENTS.md` would still do so when the post-edit hook runs it; the review's `finder-contract` reads the tests for exactly that. `decisions.json` has two belts and no proof: the guards refuse `review.mjs decide` and the file to every agent, and the script writes it only after the person types the cycle number back on the controlling terminal (`/dev/tty`, which `decide` opens itself; no option, flag, variable or test seam stands in for the answer; a process with no terminal cannot open it, and a piped answer never reaches it; the writer behind it is an internal module the kit's tests call). A program with the developer's rights can still import that module or write the file directly; there is no signature behind it, and the kit does not pretend there is.
- **An object read by its id.** `git cat-file -p <blob sha>` or `git show <sha>` can print a file a past commit held, a secret among them; the secret guard reads paths (`git show HEAD:.env` is refused), not object ids. Secrets never enter the repository in the first place (the `secrets` gate line), which is the rule that matters.
- **`echo $VAR` is unknowable.** The secret guard refuses dumps of the whole environment (direct and through `process[...]`-style indirections), reads of secret files, including through bracket globs (`.[e]nv`), and recursive reads over a folder that holds one; a single named variable cannot be told from a harmless one.
- **A judge's agent file could be edited to give it tools.** The agent files live in the kit, which no project session may write; a person who edits the kit has decided to.
- **`git config` aliases, `core.hooksPath` from outside, editing the hook scripts.** The commit guard refuses the obvious routes (`--no-verify`, `GIT_DIR=`, `core.hooksPath`, `git config` writes, `git -C`, `cd` before a commit) and the gate's installation files are the human's; a person at the terminal can still unset the hooks path. CI with `--strict` and the pinned kit is the backstop for what a person did on purpose.
- **The clerk saves the judges' answers.** `verifier.json` and `finder-*.json` are the clerk's transcription of a judge, and a careless main session could save an answer it made up. The verdict is computed from them by `review.mjs render`, which validates every id against the finders' files, and `docs/REVIEW.md` itself is refused to every agent and cross-checked by the gate against the script's `state.json`; what remains open is a forged answer file, which the human reads in `docs/REVIEW.md` next to its evidence.
- **A missing `agent_type` on `SubagentStop` resolves to the main session** and passes silently; the field is documented and present on current Claude Code, so nothing is done about an older one.
- **The gate runs the tests on the working tree, not on the index** (a standard pre-commit limitation): an index that differs from the tree is caught by CI, which checks out the commit.

What is **not** on this list, because the audit found it and the kit now holds it: `git rm`, `git mv` and `mv` as writes; a builder ticking a manual check; `cat .env*` and `printenv`; `patch`, `dd`, `tar`, `rsync` for a judge; `/usr/bin/git`, `\git`, `sh -c "git ..."`, `eval`; `gh pr merge`, `npm ci`, `git branch -D`, `git switch main`; an MCP write tool; a plan approved by a two-step edit; a `.sdlc/state.json` left in a stranger's folder; a diff too large to scan reported as clean.

All under `tools/`, plain Node, `--root <dir>` on each to point at another project.

| Tool | Usage | Prints |
|---|---|---|

| `contract.mjs` | `node tools/contract.mjs` | one line per approved document under `docs/`: `intact` (unchanged since its approval commit), `changed` (text changed after it, committed or not), `reapproving` (the Status line is changing in the working tree: a new approval), `uncommitted`; exit 1 unless every one is intact |
